## 3. 实现说明与验证

### 3.1 配置和封装

application.properties 使用环境变量占位符，Web3jConfig 不保留示例默认私钥。
Gradle 从 Solidity 源码生成 Escrow、IERC20、WQLToken、SimpleStorage 的 Java 封装。
Order 使用 DynamicStruct，金额等整数使用 BigInteger。状态代码在 Service 中转换为文字。
对应截图为 4A-1、4A-2，完整文件入口见 [截图索引](截图索引.md)。

### 3.2 Service 与 Controller

Service 封装部署、重新加载、查询与仲裁；链 ID 检查避免连接错网络。
地址与部署块保存在同一个不可变 Binding 中，异步操作使用各自取得的绑定。
部署/仲裁写入在该服务实例中串行，不能宣称这是多实例全局 nonce 协调机制。
Controller 负责参数转换、HTTP 响应与错误映射，合约负责最终角色/订单状态检查。

| 接口 | 输入 | 成功返回要点 |
|---|---|---|
| POST /api/escrow/deploy | 无 | contractAddress、transactionHash、deployBlock |
| POST /api/escrow/load | address、fromBlock 查询参数 | contractAddress |
| GET /api/escrow/address | 无 | contractAddress、arbiter |
| GET /api/escrow/orders/{id} | id 路径参数 | buyer、seller、token、amount、deadline、文字 status、description |
| GET /api/escrow/orders | 无 | OrderCreated 的 id、buyer、seller、amount、blockNumber、transactionHash 数组 |
| POST /api/escrow/orders/{id}/resolve | id 与 sellerWins 查询参数 | transactionHash、blockNumber、回执 status |

日志查询限定新合约地址和 OrderCreated topic，按每批最多 10 个闭区间区块读取，按区块/交易/日志序号排序。
RPC 错误不会伪装成空列表或返回不完整列表。列表是创建记录，不含当前状态；详情单独调用 getOrder。
参数错误返回 400，未加载或链上状态冲突返回 409，RPC/网络错误返回 502。
有失败回执时保留 transactionHash、blockNumber、status、gasUsed。
完整 Service 与 Controller 截图均已保存，见 4A-4 索引。
