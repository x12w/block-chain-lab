本次为路线A新增的卖家发货和双人仲裁补充POTOS测试网记录。增强合约已部署，你负责两笔订单的发货，再对其中一笔发起争议。买家创建、付款、退款、确认收货及第二票由魏琪霖负责；第一票由袁嘉骏负责。

**先回复组长“准备好了”，等组长完成付款并发来两笔实际订单ID后再发货。** 发货必须在订单deadline之前完成，建议两人同时在线预留15–20分钟。旧必做合约的流程已经完成，本次使用下列新合约。

## 一、准备Remix，只加载已有合约

1. 在安装本人MetaMask的浏览器打开 [Remix](https://remix.ethereum.org/)，切到POTOS Testnet，选择上表卖家钱包。
2. 下载同目录的 [BonusAcceptanceInterfaces.sol](BonusAcceptanceInterfaces.sol)。在Remix文件面板导入它，或新建同名文件并完整粘贴源码。
3. 在Solidity Compiler中使用0.8.x编译器编译该文件。本次接口已用0.8.26编译，并逐项核对了函数、返回类型和事件ABI；文件不依赖其他源码。
4. 打开Deploy & Run Transactions，Environment选择连接浏览器钱包的选项（Browser Extension/MetaMask或Injected Provider - MetaMask，按页面实际名称）。钱包连接请求中选择卖家账户。
5. 核对Remix的Account为上表卖家，网络chainId为60600，Value为0。
6. Contract选择`IRouteABonus`。在At Address填入增强合约地址，点击At Address加载；**不用点击Deploy，也不用填构造参数**。
7. 展开Deployed Contracts中的实例，只读检查`version()`返回2、`arbiter()`与`secondArbiter()`分别返回上表地址。保存包含网络、账户和合约地址的截图，然后回复组长“准备好了”。

## 二、等组长发来订单ID，核对付款状态

组长会创建三笔订单：正常发货后确认、未发货超期退款、发货后争议退款。你只操作其中两笔需要发货的订单，未发货退款那笔不操作。

新合约最初计划的正常订单ID为0、争议订单ID为2；**以组长发送的实际ID为准**。如果编号不同，下文的0、2相应替换。组长尚未通知付款完成时，不提交发货交易。

对两笔订单分别调用`getOrder(id)`，确认：

- buyer为上表买家，seller为你的卖家地址，token为上表WQLToken。
- amount为`1000000000000000000`。
- status为`1`，即Paid。`0`是Created，表示还未付款，需要等组长完成deposit。
- deadline还未到。请在组长通知付款后尽快发货；如果已经到期，先把情况告诉组长。

状态对应：Created=0，Paid=1，Completed=2，Refunded=3，Disputed=4，Shipped=5。

## 三、两笔订单分别发货

1. 在`markShipped(uint256 id)`中填正常订单实际ID（预期0），提交一次，在卖家钱包中核对网络、目标为增强合约、Value=0，再确认交易。
2. 等交易成功，保存完整交易哈希、成功回执及`OrderShipped`事件。调用`getOrder`，确认status变成`5`（Shipped），保存截图。
3. 用同样方法对争议订单实际ID（预期2）执行一次`markShipped`，保存成功哈希、事件和Shipped状态图。
4. 把两笔发货哈希发给组长。正常订单接下来由买家测试退款限制并确认收货，你无需再对它执行交易。

## 四、对争议订单发起争议

确认争议订单刚才发货成功、当前为Shipped后，在`dispute(uint256 id)`填争议订单实际ID（预期2），提交一次并由卖家钱包确认。

保存成功交易哈希、回执、`OrderDisputed`事件，再调用`getOrder`确认status为`4`（Disputed）。把这笔记录发给组长，即完成你的三笔协作交易。

后续由袁嘉骏的BE投第一票，魏琪霖用第二仲裁钱包完成意见冲突与改投演示。卖家无需调用`resolve`、`confirm`、`refund`或转交钱包私钥。

## 五、出现异常时

- 提示不是卖家：检查MetaMask当前账户和该订单seller。
- 提示状态不正确：先用`getOrder`确认是否尚未付款、已经发货或已经进入争议；不要反复点提交。
- 提示发货截止时间已过：把订单ID和deadline发给组长，不能用迟到发货替代成功验收。
- 页面报错或转圈：如果已经产生交易哈希，先在浏览器查回执，并查询订单状态；确认实际失败后再决定下一步。页面错误不一定代表链上失败。
- 钱包解锁由本人完成。回传公开交易哈希和截图即可，不发送私钥、助记词或钱包导出文件。
