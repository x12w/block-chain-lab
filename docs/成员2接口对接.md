# 成员 2：Controller 对接说明

Controller 已在 PR #1 中合并，并完成六接口本地 HTTP 联调。
实现位于 `src/main/java/com/wetech/demo/web3j/controller/EscrowController.java`，
使用 `@RestController`、`@RequestMapping("/api/escrow")` 和构造函数注入 EscrowService。
保留现有 SimpleStorageController，用于教程 4.4 的示例验收。

## 六个必做接口

| 方法/路径 | 参数 | 调用 Service | 成功返回 |
|---|---|---|---|
| POST /api/escrow/deploy | 无 | deploy() | contractAddress、transactionHash、deployBlock |
| POST /api/escrow/load | address、fromBlock | load(address, fromBlock) | contractAddress |
| GET /api/escrow/address | 无 | getAddress() | contractAddress、arbiter |
| GET /api/escrow/orders/{id} | 路径 id | getOrder(id) | buyer、seller、token、amount、deadline、status、description |
| GET /api/escrow/orders | 无 | listOrders() | id、buyer、seller、amount、blockNumber、transactionHash 的数组 |
| POST /api/escrow/orders/{id}/resolve | 路径 id、sellerWins | resolve(id, sellerWins) | transactionHash、blockNumber、status |

POST 参数按教程使用 query parameter（@RequestParam），不要求请求体。
数量、区块、订单编号用 BigInteger；JSON 中大整数建议用十进制字符串，避免浏览器精度损失。
getOrder 的 status 为 Created/Paid/Completed/Refunded/Disputed。
resolve 的 status 来自交易回执（0x1 或 0x0），订单业务状态应再调用 getOrder 查询。

## 异步返回和错误

- deploy() 返回 CompletableFuture<Escrow>。在 thenApply 内从返回的合约获取地址与部署回执，
  从回执读取 transactionHash、blockNumber。不要依赖随后可能被 load 改变的全局绑定取本次响应。
- getAddress()/getOrder() 返回 CompletableFuture<Map<String,String>>；可直接组合响应。
- listOrders()/load() 会抛 IOException；日志查询失败要返回错误，不要返回空数组掩盖漏单。
- resolve() 返回 CompletableFuture<TransactionReceipt>。CompletionException 中可能包着
  TransactionException；向下查找 cause，保留其中的 transactionReceipt。
- 建议参数错误 400、尚未加载合约 409、链上执行失败 409、RPC 故障 502。
  Web3j 的只读调用回滚会抛 ContractCallException；该异常带回滚信息时也须映射为 409。
  错误 JSON 附 message；有失败回执时再附 transactionHash、blockNumber、status、gasUsed。
  不输出私钥、完整堆栈或内部配置。
- 不要在 Controller 中提前把教程“订单 0 仲裁失败”拦掉：需要真实验证合约的状态检查。
  有回执才能写“失败已上链并消耗 gas”；估算失败/网络失败不一定有链上交易。

## 事件列表已经具备，可直接接入

Service.listOrders() 已实现 OrderCreated topic 编码、合约地址过滤、每批最多 10 个区块、
事件解码和区块顺序排序。成员 2 负责接入、复核及 HTTP 层验收，避免重复写一套查询逻辑。
fromBlock 必须保存后端新部署的真实区块号。应用重启后用 /load 恢复，无需重复部署。
